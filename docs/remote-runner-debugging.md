# Debug a retained remote runner

The reusable action in `.github/actions/debug-failed-runner` opens an SSH session on the original runner. It accepts a public SSH key; the client keeps the private key. The connection artifact contains the SSH command and workspace path. Use the repository's `known_hosts` file to verify the relay, and supply the private key with `ssh -i` and `IdentitiesOnly=yes`.

Run `.github/workflows/runner-debug-smoke.yml` with `public_key` and one selected `target` to exercise this without compiling Codex. The action waits during job cleanup for up to ten minutes for the first connection. After a client joins, the session remains available until its shell exits or the job reaches its own timeout. The smoke workflow has a sixty-minute job timeout. Exiting the remote shell lets cleanup finish; it preserves the original failed step's result.

When testing changes to a remote-runner workflow, follow [remote-runner-testing.md](../.cat/rules/remote-runner-testing.md): open and authenticate the session before the changed commands run, and keep the connection open through testing and incremental troubleshooting. A failure-only invocation does not satisfy this requirement. Retrieve `.github/actions` and invoke the action with the client's public key before those commands. The [compiler diagnostic workflow](../.github/workflows/scheduler-compiler-allocations.yml) waits for the connected client to create `client-ready` in its owned diagnostic directory; only then does compilation start. The client remains connected until the test's `probe-exit` receipt is available, and can inspect the retained log and retry before exiting.

The action is detached, so ordinary steps continue immediately while its wait occurs during post-job cleanup. Register workspace cleanup as an earlier action's post operation so that reverse post order runs it after the remote session ends. Ordinary steps must not delete the workspace that the session needs. The historical failure smoke fixture demonstrates this cleanup ordering and verifies retained state in its own post operation; it does not establish connection before testing.

In the remote shell, inspect the actual failing command and environment before changing anything. Retain valid build outputs, apply the focused correction and retry incrementally. Keep the original failure and retry evidence separate. After incremental success, perform the task's required clean verification. A completed or destroyed runner cannot be recovered through this session; use retained logs and valid partial caches for a replacement runner.
